# 产品提案：评审现场化社区——主题的自证

日期：2026-11-15 · 状态：**提案 v2，待用户定稿**
来源：2026-11-15 定位访谈（招牌功能优先、四主轴全选）+ 用户反馈"增强与项目主题关联性"。

## 一句话

**社区机制本身演示项目主题。Nexus-Vibe 的主题是"把 LLM 当不可靠依赖"（fail-closed、租约、修复重试、降级可服务）——这些至今只是仓库里的工程事实；本提案让它们成为社区的公共生活：不可靠被公开围观，失败有舞台，纠正有轨迹，证据有档案。别的论坛把 AI 包装得可靠完美（这正是"AI 流水线味"的来源），本社区反向操作：诚实的 AI，就是招牌。**

四个主轴因此不是"社区 + AI 功能"，而是**主题的四个外显面**：

```
发帖 → [评审现场]  → [共裁闭环]   → [解决沉淀]   → [证据档案]
       不可靠被围观    人机协作裁定    纠正轨迹入库    证据文化成声誉
       (fail-closed)  (人与不可靠AI)  (repair-retry) (claims纪律)
```

## 主题映射表：每个 ADR 概念的公共面

| 主题概念（工程事实） | 公共面（社区看得见的形态） | 落点 |
| --- | --- | --- |
| LLM 是不可靠依赖（ADR-0006） | 评审现场直播**真实的**重试、校验失败、降级——不成功也上舞台，"AI 不确定"是现场的一部分而非异常 | S1 |
| Fail-closed（ADR-0004） | 公共审核队列：PENDING_REVIEW 帖子可见可围观，社区亲眼看"AI 拿不准时人接管" | S1/S2 |
| 人与不可靠 AI 协作（ADR-0017 评论先可见后检查） | 共裁机制：AI 结论可被社区认同/质疑，闭环由两者合成——AI 失败处正是人类的接口 | S2 |
| Repair-and-retry（AbstractLlmReviewer 的修复梯子） | replay 墙展示同帖多次尝试的**纠正轨迹**：无效→强化提示→有效，知识库条目沉淀的不只是答案，还有"AI 是怎么被纠正的" | S1/S5 |
| Review Validity（语义校验门） | AI 公民发言带校验状态（通过/降级/重试），社区可质疑可追溯——诚实的 AI 公民 | S3 |
| 证据文化（AGENTS.md：声称必须有可复现路径） | 声誉系统：档案里每个数字都可点开原始评审日志——项目自己的纪律变成用户的声誉 | S4 |
| Degraded-but-serving（ADR-0007/0019） | capabilities 闭合词表直接驱动社区 UI：站点降级时哪些功能受限、为什么，公开呈现而非静默 | 全程 |
| 租约与对账（ADR-0005） | 现场化广播的真实状态机：围观者看到的就是租约/对账在跑，不是假动画 | S1 |

**这条表就是创新性的论证**：每个主题概念都获得一个别的论坛做不出来的公共形态，因为那些概念只在这里被当真实施过。

## 与"AI 流水线味"的总清算

用户 2026-11-14 的抱怨"AI 流水线味重"在 v2 提案里得到原则性解答：流水线味 = **假装可靠**的 AI 美学（霓虹、假动画、装饰性科技感，AI 从不失败从不迟疑）。设计轮的 forge 转向（ADR-0020）负责去掉假装；本提案负责**把真实立起来**——真实的评审有失败、有重试、有降级，公开它们不是丢丑，是主题本身。设计与产品在同一个原则上会师：**不撒谎的 AI 界面**。

## 功能切片（主题关联性排序，每片独立可验收）

**S1 评审现场（不可靠被围观）**
帖子详情页评审盒升级为真实进度广播（领取→评审→校验→回帖，轮询 agent-logs 起步，SSE 升级项）。关键差异：**失败路径与成功路径同台**——重试中、校验失败、fail-closed 入队列都是现场事件，replay 标注照旧（ADR-0010 规则演化为"只有真实是实时"）。

**S2 共裁与闭环（人类的接口）**
AI 结论可被社区认同/质疑（复用 sentiment 列），作者可标"已解决"，闭环状态由 AI 评分 + 社区确认在服务端合成。AI 降级或 fail-closed 时，共裁界面显式呈现"现在由人裁定"——主题里人与不可靠 AI 的协作点。

**S3 AI 常驻公民（诚实的成员）**
debug 频道无人应答时 AI 自动抢答（复用 Mention 的占位/冷却/租约）；AI 发言带校验状态与来源，其历史发言聚合页展示它被认同/质疑/纠正的记录。**AI 的不可靠在档案里如实可见**——这是"AI 公民"与"聊天机器人"的分界线。

**S4 证据档案（声誉即证据）**
个人主页六格统计升级：AI 评分曲线、被采纳建议数、解决他人问题数、共裁参与度，**每个数字可点开到原始 ai_review_log 行**——证据文化的产品化。数据全部来自既有表。

**S5 知识库（纠正轨迹入库）**
已解决帖子的沉淀视图 + 语义近邻推荐（ES 降级路径沿 ADR-0011）。条目包含评审的纠正轨迹（无效→重试→有效）——知识库沉淀的是"答案 + AI 是怎么被纠正的"，这是别的知识库没有的维度。

## 诚实约束

- ADR-0009 重开需新 ADR（0022，若提案采纳）。
- S2 的闭环状态与共裁计数是 schema 变更（走迁移演练链路）；S1 的进度广播需管线打点（ADR-0014 defer 缝是落点）；S3/S4/S5 不动 schema。
- 全部按验收链路走（契约冻结 → 独立实现 → 独立 Verifier）。
- 冷启动诚实说：真实社区需要人；招牌功能先让作品集有辨识度——"主题自证的社区"本身就是面试叙事里最难复制的一章。

## 与设计改造轮的关系

地基与楼不变：forge 设计轮（shell/token/i18n/密度）先冻结开工。本提案增加的唯一设计侧输入：**AI 相关界面（评审卡、现场条、AI 档案页）遵循"不撒谎的 AI 界面"原则**——真实状态优先于装饰，失败态与成功态同等设计待遇。此原则补入 v2 规范的设计原则第 6 条（改动一行，不扩大设计轮范围）。
